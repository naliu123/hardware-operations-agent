## 1. 交付顺序

优先通过普通问答建立知识匹配、引用和模型效果基线，再验证 Plan–Execute–Replan。每个任务包含从输入到可观察结果的完整路径；基础设施与对应功能一起交付。

任务实现遵循 Go + Eino 约定：应用入口使用 `cmd/`，业务代码使用 `internal/`，依赖锁定在 `go.mod` 与 `go.sum`。模型、Retriever 和工具通过 Eino 接入；业务校验、持久化、设备适配、回放评测及测试均使用 Go。

| 阶段 | 任务 | 完成后可验收的能力 |
| --- | --- | --- |
| M1：普通问答 | QA-01～QA-06 | 知识问答、配置指导、设备状态查询、多轮澄清和首批评测 |
| M2：只读持续诊断 | DX-01～DX-02 | 根据实际证据重规划、并行检查、持久化与恢复 |
| M3：主动排查与协作 | EV-01、EX-01～EX-02、HC-01 | 高优先级告警触发、拓扑关联、动态 CLI 审核、现场协作 |
| M4：综合验收 | PF-01～PF-02 | 历史回放、三类诊断路径、128/256 活跃诊断容量评估 |

模型效果需要真实模型评测，生产接入需要真实资料与接口。确定性模型、合成手册、回放监控和模拟命令用于开发验证，结果标记为模拟或回放，不计作真实设备或生产效果验收。

## 3. M1：普通问答

### QA-01：从已发布知识得到带引用的回答

**交付行为：** 导入一份资料，经发布后提交问题，取得答案并打开对应原文。以 Go 实现最小 HTTP 会话入口、知识修订、检索与模型适配器及结果持久化，通过 Eino Graph/Chain 串起召回、生成和校验。

本任务同时初始化 Go 工程、锁定兼容的 Eino 依赖，并通过确定性 ChatModel 与 Retriever 实现打通 Eino 调用。数据库访问和迁移沿用技术设计的 Go 配套默认值。

先以可提取文本和已复核内容建立流程；PDF 文本提取接入后必须保留章节、页码和命令上下文，扫描或解析失败资料明确返回待处理状态。

**验收条件：**

- [x] 未发布资料不会进入可用答案依据；已发布片段可以回到确切修订和原文位置。
- [x] 回答的核心结论关联实际召回片段，不能引用不存在的片段。
- [x] 配置方法仅作为指导输出，问答入口不下发设备命令。
- [x] 模型接口不可用时返回明确错误，不用固定答案冒充模型成功。
- [x] 本地确定性数据可完成请求到结果的集成验证；真实模型验证结果单独记录。
- [x] Go 工程可构建，Eino 问答图可编译并被集成测试实际调用，`go test ./...` 通过。

**实施记录（2026-09-19）：** Go + Eino HTTP 后端和演示入口已交付，编译、vet、race 测试及服务进程演示通过。当前使用通用文本资料、词项检索和开发文件存储完成确定性验收；PostgreSQL 适配器已提供，真实数据库和内网模型未联调。验证证据与范围见 [QA-01 工单](../../.scratch/hardware-operations-agent/issues/01-qa-01.md)，启动方式见 [README](../../README.md)。

### QA-02：同一问题匹配正确的型号与版本

**交付行为：** 接入设备身份及版本上下文，使同一指示灯、错误码或配置问题在不同设备上使用相应资料。

**验收条件：**

- [x] 覆盖至少两种测试型号、每种两个版本的对照样本，设备与版本通过明确标识区分。
- [x] `MATCH`、`MISMATCH`、`UNKNOWN` 有独立测试；缺失版本不能按最新版本默认回答。
- [x] 版本比较遵循产品规则，无法比较时返回未知。
- [x] 设备别名存在多个候选时先澄清；通用问题不要求无关的版本信息。
- [x] 切换设备后不会沿用上一个设备的型号、版本或引用。

**实施记录（2026-09-19）：** 已交付设备快照与名称解析、产品版本顺序、三态适用性、每条消息的独立上下文及生成期间更新保护。13 个新增 HTTP 场景测试、QA-01 回归、race、vet、构建及四组型号版本的服务进程演示通过，全部确定性结果标记 REPLAY。真实数据库、模型、资产和正式版本规则未联调，见 [QA-02 工单](../../.scratch/hardware-operations-agent/issues/02-qa-02.md)。

### 03a：指定文档的Elasticsearch / Phoenix真实RAG实验

**交付行为：** 依据用户新增需求，以ES为文档及向量库、本地BGE小型中文模型、DeepSeek `deepseek-flash`完成真实文档检索与问答，在Phoenix中保存数据集、追踪和实验，并以冻结验收集Recall@5≥60%验收。

**实施记录（2026-09-20）：** Go公开HTTP接入ES/BGE与OTel/OpenInference；华为云CCE《高危操作一览》的55行证据及前言已入库。冻结66题（开发25、验收41），开发BM25→Dense/RRF比较后选Dense，开发Recall@5由97.83%提升至100%；独立验收38道可回答题的Recall@5为93.42%。真实生成66次、模型评审66次，Phoenix回读2个数据集、6个实验、182个run和607个span；全量race、vet与构建通过。模型评审与确定性流程检查单列，错误案例保留。主应用为Go + Eino，Python只用于本地模型服务及评测编排。

证据与复现见[03a工单](../../.scratch/hardware-operations-agent/issues/03a-rag-es-phoenix.md)、[统计报表](../../reports/rag-cce-20260920/report.md)。此次单页资料评测不替代QA-03全部纠偏行为、QA-04实时状态或QA-06综合验收；具体资源停止记录见报表。

### 03b：CCE用户指南全目录入库

**实施记录（2026-09-20）：** 固定757个唯一导航节点，其中116个分类节点仅进入导航清单，641篇实际文档全部采集并发布；语料总计6149442 UTF-8字节，形成641个不可变修订和3539个检索片段。发布使用REPLAY模型模式，embedding为真实本地BGE推理。ES计数、两个稳定别名、文件哈希及5组跨目录BM25/Dense检索均核验通过；全量race、真实ES/BGE公开HTTP流程、vet与构建通过。

采集与发布支持checkpoint续跑，目录或正文哈希变化时拒绝混用旧索引。证据与复现见[03b工单](../../.scratch/hardware-operations-agent/issues/03b-cce-full-manual-ingestion.md)、[全目录入库报告](../../reports/rag-cce-manual-20260920/report.md)和[RAG运行说明](../../scripts/rag/README.md)。

### 03e：RAG内部知识检索子 Agent

**交付行为：** 将查询改写、检索、适用性复核、证据选择、引用和缺口收敛为内部Eino子Agent，通过`retrieve_hardware_knowledge` AgentTool供主Agent调用。

**实施记录（2026-09-25）：** 子Agent只接收自包含的知识问题，可信设备快照由运行上下文注入；返回结构化证据、引用、适用性、实际检索问题、缺口、trace和数据模式。该阶段问答Graph通过AgentTool确定性取证，最终答案生成和引用复核由主流程负责。确定性工具与公开HTTP回归标记为REPLAY；模型自主tool-call协议由后续03h交付。证据见[03e工单](../../.scratch/hardware-operations-agent/issues/03e-rag-knowledge-subagent.md)。

### 03h：主 Agent 自主调用 RAG 子 Agent

**交付行为：** 将`retrieve_hardware_knowledge`注册给主模型，模型决定是否检索、查询内容及是否继续。Eino Graph承载模型和工具循环，最终答案进入原有引用与设备校验。

**实施记录（2026-10-01）：** OpenAI适配器实现不可变`WithTools`及原生工具请求/响应协议；主循环最多三次知识调用、累计证据48 KiB，拒绝重复查询和非法参数。响应持久化逐次`knowledge_tool_calls`及失败记录。公开HTTP与外部模型桩验证改问重查、无检索、设备身份、调用预算、证据去重、引用和重启记录，结果标记REPLAY；全量race、vet、构建通过。

真实`deepseek-v4.1-flash`通过隔离临时库和公开HTTP完成一次知识工具调用、两次模型调用，答案引用可回读。该烟测使用合成手册和本地词项检索，不代表CCE全量质量或生产设备验收；查询改写及证据选择未在此次真实烟测启用。证据与复现见[03h工单](../../.scratch/hardware-operations-agent/issues/03h-main-agent-rag-tool.md)。

## 4. M2：只读持续诊断

### DX-01：通过实际查询结果推进 Plan–Execute–Replan

**交付行为：** 提交一个有适用排障方案的错误码事件，以 Eino Graph 的 Plan、Execute、Replan 及校验节点生成计划、执行只读检查，并根据返回结果调整后续计划。

**验收条件：**

- [ ] 保存初始计划、候选原因、依赖和确认条件，步骤目的与实际观察分开记录。
- [ ] 改变检查结果后，后续检查或判断产生符合证据的变化。
- [ ] 就绪步骤只在依赖与前置条件满足时执行；无效计划不能下发。
- [ ] 复用有效证据时保留依据，工具失败不转化为设备故障结论。
- [ ] 根因确认、故障恢复和本次运行完成分别记录；预算耗尽时输出缺口。
- [ ] Eino 图的条件分支实际覆盖继续、等待、暂停和完成，Go 结构化提案通过业务校验后才可提交。

### DX-02：并行检查、重复事件和中断恢复

**交付行为：** 多个独立检查可以并行，计划修订与迟到结果可以共存，Go worker 中断后依据业务状态与 Eino 检查点恢复正确状态。实现 PostgreSQL `CheckPointStore` 适配及运行、图版本、检查点映射。

**验收条件：**

- [ ] 两个 worker 使用旧版本提交时，只有合法版本更新被接受。
- [ ] 重复事件不重复应用；迟到结果归入原步骤并接受当前适用性判断。
- [ ] outbox 补发、Eino 恢复时节点重入不会生成重复业务操作。
- [ ] 多个等待理由同时存在，任一有效反馈可以推进相关分支。
- [ ] 挂起释放活跃额度；恢复不重置预算、不清空证据历史。
- [ ] 覆盖跨 worker 恢复、检查点落后及图版本不兼容，状态以业务记录为准；相关并发测试通过 `go test -race`。

## 5. M3：主动排查、审核执行与现场协作

### EV-01：高优先级告警自动诊断并关联拓扑

**交付行为：** 高优先级告警建立或关联事件，自动开展只读排查；根据有效拓扑追查共同依赖。

**验收条件：**

- [ ] 告警优先级按实际监控映射配置，重复通知追加至同一事件。
- [ ] 拓扑关系和时间重合只形成候选关联，共同原因证据满足后才合并。
- [ ] 反对证据可触发拆分，操作和审批仍对应原目标。
- [ ] 恢复后再发生成新事件；延迟到达的旧告警按实际发生时间归属。
- [ ] 自动事件需要命令或变更时保存待审核事项，等待处理对话。

### EX-01：当前对话用户审核动态 CLI 与变更

**交付行为：** 主 Agent 生成具体操作，用户查看原因与手册出处后决定，执行结果返回诊断流程。Eino 工具封装调用 Go 操作模块，Graph 等待或中断恢复必须经过业务审批校验。

**验收条件：**

- [ ] 动态生成的查询 CLI 与状态变更均需审核，已接入只读工具可自动调用。
- [ ] 审批展示目标、完整操作、原因及出处；没有手册依据时如实标记。
- [ ] 审核用户来自当前处理对话的认证身份，不能通过请求体伪造。
- [ ] 同意只改变执行条件，不添加虚构诊断证据；拒绝后不执行。
- [ ] 修改目标、命令或参数形成新的审批对象；按原内容批准的单次操作不被重复下发。

### EX-02：命令结果不明时核对状态

**交付行为：** 命令下发前后任意中断，恢复流程保留真实状态，并优先核对设备实际结果。

**验收条件：**

- [ ] 覆盖下发意图入库后、调用设备后和回执入库前中断的情况。
- [ ] 不确定结果标记 `UNKNOWN`，不会仅因重试或重规划重复下发变更。
- [ ] 有远端操作标识时核对原操作；没有时按适配器能力查询实际状态。
- [ ] 迟到回执归入原操作，同设备冲突变更等待核对。
- [ ] 模拟执行验证与真实设备联调记录分开，不把模拟回执记作真实执行成功。

### HC-01：现场检查、跨班次继续与恢复观察

**交付行为：** 将远程无法完成的检查交给人员，接收文字、照片或测量结果，恢复诊断并按故障类型验证恢复。

**验收条件：**

- [ ] 任务包含设备和部件位置、方法、观察要求及停止条件。
- [ ] 反馈附带目标、时间、单位和人员；错误任务或设备的反馈不进入当前证据。
- [ ] 等待期间挂起，独立分支仍可执行；跨对话恢复时刷新必要上下文。
- [ ] 照片推断保留适用范围，不把不可见状态写成确定事实。
- [ ] 观察窗口由定时任务推进，根因未知但已恢复等组合状态可以表达。

## 6. M4：综合验收

### PF-01：三类诊断路径的历史回放

**交付行为：** 以明确错误码、拓扑关联、现场协作案例评测完整诊断，保留每次计划变化与证据。

**验收条件：**

- [ ] 运行数据、知识与历史工单均受回放时间和案例血缘约束。
- [ ] 最终维修结论、后续材料及其重复副本仅供评分侧使用。
- [ ] 缺少检查记录时返回缺失，回放不会执行生产设备命令。
- [ ] 统计根因命中率、错误确认比例、覆盖率、检查有效性和定位耗时。
- [ ] 多根因、无足够证据和型号版本不匹配的案例单独分析。

### PF-02：128/256 活跃诊断容量评估

**交付行为：** 对问答和诊断混合负载、集中告警及大量挂起任务唤醒进行容量测试。

**验收条件：**

- [ ] 分别测试 128 和 256 个集群活跃诊断，记录设备数、归并后到达率与自动排查时长。
- [ ] 单独测量模型调用并发、token 吞吐、工具查询和下游限流。
- [ ] 后台负载下普通问答仍有预留资源，记录实际延迟分布。
- [ ] 挂起任务不占活跃额度，多个 worker 的额度总和符合配置。
- [ ] 模型、监控接口或硬件不足时报告实际瓶颈和可支撑容量，不直接宣布十万卡目标已达成。
