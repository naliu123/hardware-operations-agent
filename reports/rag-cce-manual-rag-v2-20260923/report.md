# CCE手册RAG语义增强报告

## 结论

已为641篇CCE手册建立`hwops-cce-manual-v2`索引，并将稳定别名
`hwops-cce-manual`切换到该版本。新流程包含LLM语义拆分、片段问题生成、
表格/图片语境描述、多向量索引，以及用户问题改写后的并行混合召回。

本次按要求只运行一轮正式RAG评测，模式为`REAL_RETRIEVAL_ONLY`，未生成答案、
未运行答案评审。该轮发生7个查询改写协议错误，69道可回答题的宏平均
Evidence Recall@5为86.23%，完整证据命中率为84.06%（58/69），
Document Hit@5为84.06%，p95为5.75秒。结果未达到旧RRF=1开发基线，
不能声称本轮优化提升了召回质量。

评测后根据该轮证据修复了查询改写可靠性和融合偏置，但遵守“只跑一轮”要求，
没有再次运行正式评测。最终实现仅通过跨目录公开检索验证，不能用该验证替代
新的完整评测结果。

## 查询实现

- 原问题始终保留，LLM生成至少两个非占位改写。
- 各问题通过Eino Retriever接口并行执行；发布状态、设备适用性和Top K选项
  原样传入每一路。
- 每一路内部执行BM25与nested dense检索；查询间使用RRF=1融合，并给予原问题
  2倍权重，避免强词项证据被多个泛化改写淹没。
- 正文、每个问题、每个表格描述、每个图片描述分别向量化；长正文使用有重叠的
  bounded PASSAGE表示。任一表示命中后只返回绑定的原始片段。

## 唯一评测轮次

产物：

- `rag-v2-development-once.json`
- `rag-v2-development-once.md`
- `rag-v2-development-once-badcases.json`

配置：75道development题、Top K=5、每路候选20、hybrid、RRF=1、
多向量开启、查询改写开启、Qwen 3B本地改写模型。

该轮7个错误均发生在查询改写输出契约，未进入检索；另有5题未命中全部参考锚点。
评测暴露的两个实现问题及后续修复：

1. 本地模型有时只返回一条改写或返回`问题1/问题2`占位文本。最终实现改为最多
   三次有界累积、兼容`QUERY:`行、拒绝占位文本，并要求至少两个不同改写。
2. 查询间RRF=60过度奖励多个泛化改写共同命中的片段。最终实现改为RRF=1并给
   原问题2倍权重，保留精确词项信号。

这些修复后的最终版本通过5组BM25和5组Dense跨目录公开检索，10/10命中预期
来源；按照任务约束未再运行第二轮完整评测。
