# WB-02 验收记录

日期：2026-10-04。会话管理、持久化历史、有界上下文、取消及删除完成。
附件与执行产物接入后，将在 WB-04/WB-06 复验对应历史和文件清理；本报告不代表
Python、真实正文流或完整工作台已经交付。

## 行为与实现

- 迁移 006 增加会话删除标记、消息序号、唯一活跃响应索引、摘要和清理任务。
  既有历史原位分配稳定序号，继续核对迁移校验和及实际数据库结构。
- 提交事务锁定会话，统一裁决归属、幂等、上下文版本与活跃任务冲突；
  同键同内容返回原响应，同键不同内容及同会话第二个活跃请求返回 409。
- 标题由第一条问题确定性截取，避免引入影响聊天的命名模型调用；
  手动标题使用状态版本 CAS，后续提交不覆盖手动标题。
- 历史和搜索直接限定 owner 及未删除状态。搜索只纳入标题、用户问题和已定稿答案；
  按创建时间与 ID 分页，消息按稳定序号分页。
- 最近六轮和增量摘要进入实际模型输入。每次最多压缩四轮；摘要保存覆盖范围、
  版本和原引用，原消息不删除。失败、中断和取消记录不携带假定成功的答案；
  旧设备观测值不进入历史证据，新的知识结论需重新检索。
- 历史输入上限 48 KiB；摘要记录上限 24 KiB，其中摘要文字上限 6,000 字节。
  超限或摘要失败明确终止本轮，原记录保留，不静默截断。
- 工作台从受理起共用五分钟时限、每轮最多 20 次模型调用（含摘要及 HTTP 重试）；
  默认配置模型容量 131,072 tokens、输入预算 98,304、输出至多 8,192。
  输入使用包含工具和消息框架的保守 UTF-8 字节估算，配置必须低于模型容量。
- 不同会话最多十轮并行调度。取消先持久化 CANCELING，再取消模型请求；
  请求退出后记录 CANCELED。服务重启将未完成任务记为 INTERRUPTED，不自动重跑。
- 删除事务先禁访、取消并记录清理任务；后台等待工作退出后清理消息、事件和摘要，
  仅留删除标记和清理元数据。失败记录次数与错误码，可自动重试；迟到保存被拒绝。

## PostgreSQL + 外部 REPLAY 模型

PostgreSQL 17.11；每项 WB 验收创建并删除独立真实临时数据库。公开 HTTP 经账号
认证进入实际应用与 Eino 图，只有模型及监控使用外部 HTTP 桩。

`test/acceptance/workbench_conversations_test.go` 验证：

- 九轮问答后的最近轮次、摘要范围和原引用；实际模型输入包含真实前轮答案。
- 摘要失败明确报错、原始历史保留、显式重试追加并关联原记录。
- 另一用户及管理员不能搜索、读取、改名或删除他人会话。
- 双请求幂等、第二活跃请求 409、跨会话两个模型请求实际同时进行。
- 模型取消传播、迟到答案不覆盖取消、服务重启不增加模型调用。
- 运行中删除立即禁访并停止模型；真实数据库触发器制造清理失败，
  移除故障后任务自动重试完成；删除后的幂等重发也返回 404。
- 上下文超限明确失败；后轮设备读数从 500 rpm 更新为 650 rpm，
  外部模型历史中没有旧 500 rpm 值。

知识工具并给出已校验引用，两轮均为 ANSWERED / LIVE。
