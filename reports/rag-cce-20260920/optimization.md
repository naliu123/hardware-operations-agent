# 开发集优化记录

只使用冻结开发集观察错误；验收集在选定配置后运行。主指标始终为可回答问题的宏平均 Recall@5，不改题、不增加 k、不把无答案问题计入召回率。

## 基线：BM25 + CJK

真实 Go HTTP → Elasticsearch；25 题中 23 题可回答。

- Recall@5 = 97.8261%；Recall@1 = 80.4348%；MRR@5 = 91.3043%。
- cce-q060：比较删除 ELB 实例与删除监听器，只召回监听器相关证据，遗漏实例删除；长问题里的重复词可能主导 BM25 排序。
- cce-q012：误删工作节点，首位却是特权容器运行 systemctl；“工作节点”对象与“删除”的组合没有排到首位。
- cce-q014：普通 Node 重装系统，控制节点版本排第一，工作节点版本第二。
- cce-q039：私有 IPv4 地址变更，公网 IP 解绑排第一。

基线已经超过用户的 60% 目标，仍针对上述排序和比较题漏证据进行迭代。不能为了显得优化有效而人为降低基线。

## 下一轮假设

使用真实 BGE 小型中文模型的 dense 检索补足语义，再测试客户端 RRF 融合（两路各 20、常数 60、最终 5）。比较对象、Node 中文别名和私有/公网区别可能从语义信号受益。仅依据开发集 Recall@5 选配置，同分再看 MRR@5、Recall@1 和时延。

## 第一轮结果

| 策略 | Recall@5 | Recall@1 | MRR@5 | nDCG@5 | HTTP p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 | 97.8261% | 80.4348% | 91.3043% | 92.1711% | 9.33 ms |
| Dense BGE | 100% | 67.3913% | 81.8841% | 86.2301% | 17.26 ms |
| BM25 + Dense RRF | 97.8261% | 80.4348% | 91.3043% | 92.5202% | 16.00 ms |

Dense 补齐 cce-q060 的两项证据；等权 RRF 仍漏掉其中一项。根据预先约定的主指标，选择 Dense 作为最终检索候选。代价是前位排序下降，不能宣称所有指标都提升。语义召回更完整不意味着第一条答案更准确，生成仍使用 5 条候选并检查引用。

此处的时延来自小语料本机实验，Dense 与 RRF 两次开发实验并行运行，不能作为严格的性能对照。后续最终验收单独运行。
