# 05: QA-05 多轮追问、重复请求与连接恢复

**Task:** QA-05

**Blocked by:** 01 (QA-01)

**Status:** done

**Spec:** [总体设计](../../../docs/design/hardware-operations-agent-overall-design.md) · [Go + Eino 技术设计](../../../docs/design/hardware-operations-agent-technical-design.md)

**交付行为：** 用户补充设备信息或继续追问时保持正确上下文；刷新页面或连接中断后可取得已有响应。

**验收条件：**

- [x] 已确认设备支持指代复用；冲突上下文需要重新解析。
- [x] 同键同内容重复请求返回原响应，同键不同内容返回冲突。
- [x] SSE 从已保存事件序号续读；连接中断不重新创建问答任务。
- [x] 未校验的模型输出不作为最终操作建议直接推送。
- [x] 排队、调用超时和总预算耗尽有可理解的状态或缺口输出。

2026-10-03：消息接口支持会话内`Idempotency-Key`，受理、上下文变更与accepted
事件原子写入。只有明确指代才继承已确认目标，并重新读取设备快照；新设备独立
解析，歧义清除默认目标。可提交`context_revision`拒绝过期会话上下文。
结果保存与递增SSE事件同事务，断线不取消worker，终态事件只包含已校验结果。
文件库及PostgreSQL均实现原子路径，后者新增003迁移。

通用问题、指代歧义、重启、SSE断线续读及排队超时。全量race与vet通过；
新增排队时限场景单独race通过。确定性结果为REPLAY；PostgreSQL集成测试
因未配置`HWOPS_TEST_DATABASE_URL`跳过，未计作真实数据库验收。
