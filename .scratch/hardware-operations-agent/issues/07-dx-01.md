# 07: DX-01 通过实际查询结果推进 Plan–Execute–Replan

**Task:** DX-01

**Blocked by:** 06 (QA-06)

**Status:** done

**Spec:** [总体设计](../../../docs/design/hardware-operations-agent-overall-design.md) · [Go + Eino 技术设计](../../../docs/design/hardware-operations-agent-technical-design.md)

**交付行为：** 提交一个有适用排障方案的错误码事件，以 Eino Graph 的 Plan、Execute、Replan 及校验节点生成计划、执行只读检查，并根据返回结果调整后续计划。

**验收条件：**

- [x] 保存初始计划、候选原因、依赖和确认条件，步骤目的与实际观察分开记录。
- [x] 改变检查结果后，后续检查或判断产生符合证据的变化。
- [x] 就绪步骤只在依赖与前置条件满足时执行；无效计划不能下发。
- [x] 复用有效证据时保留依据，工具失败不转化为设备故障结论。
- [x] 根因确认、故障恢复和本次运行完成分别记录；预算耗尽时输出缺口。
- [x] Eino 图的条件分支实际覆盖继续、等待、暂停和完成，Go 结构化提案通过业务校验后才可提交。

**实施与证据（2026-10-03）：**

- `internal/diagnosis`：Eino Graph、结构化提案校验、逐步执行与重规划、持久化
  WAIT/PAUSE、恢复及取消；发布规则控制根因与恢复确认。
- 文件与PostgreSQL实现事件/运行聚合、版本CAS和原子快照/发布检查，新增004迁移；
  所有计划、执行、预算与递增事件保留。文件存储发布独立快照，避免切片别名绕过事务。
- 公开HTTP、真实临时文件库、外部模型与监控REPLAY桩：14项顶层诊断测试通过。
  全量race通过88项顶层测试，vet与build通过；逐项证据见
  [验收报告](../../../reports/diagnosis-20261003/README.md)。
- 真实`deepseek-v4.1-flash`：3版计划、3次模型、2次工具调用，监控未配置后暂停，
  根因/恢复均UNKNOWN。首轮模型引用失败观测被拒绝，明确提示协议后复测通过；
  合成手册与设备，不代表真实硬件诊断质量。
