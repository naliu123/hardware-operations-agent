# 02: QA-02 同一问题匹配正确的型号与版本

**Task:** QA-02

**Blocked by:** 01 (QA-01)

**Status:** done

**Spec:** [总体设计](../../../docs/design/hardware-operations-agent-overall-design.md) · [Go + Eino 技术设计](../../../docs/design/hardware-operations-agent-technical-design.md)

**交付行为：** 接入设备身份及版本上下文，使同一指示灯、错误码或配置问题在不同设备上使用相应资料。

**验收条件：**

- [x] 覆盖至少两种测试型号、每种两个版本的对照样本，设备与版本通过明确标识区分。
- [x] `MATCH`、`MISMATCH`、`UNKNOWN` 有独立测试；缺失版本不能按最新版本默认回答。
- [x] 版本比较遵循产品规则，无法比较时返回未知。
- [x] 设备别名存在多个候选时先澄清；通用问题不要求无关的版本信息。
- [x] 切换设备后不会沿用上一个设备的型号、版本或引用。

## 实现约定

沿用技术设计 10.1 的 HTTP 验收接口；使用真实临时存储，仅替换外部模型。首先验证两型号各两版本的带引用问答，再逐项补齐未知、范围规则、歧义和上下文隔离。

- 提供设备快照录入和解析接口，缺失字段保留未知。每个问题固定独立设备快照及 `context_revision`，不自动沿用上个问题的设备；多轮指代复用由 QA-05 交付。
- 固件、驱动和硬件修订分别精确匹配；范围使用显式登记的、绑定型号的不可变版本顺序规则，不推断厂商版本的字典序或语义版本顺序。
- 检索输出记录 `MATCH`、`MISMATCH`、`UNKNOWN` 及逐字段原因；仅 `MATCH` 片段进入模型，生成后重新校验。
- 未提供真实资产和产品版本规则时，使用明确标注为 REPLAY 的合成样本验收，真实接入单独记录。

## 交付与验收记录（2026-09-19）

- 新增设备快照 PUT、名称/别名解析、不可变产品版本规则 POST/GET；消息支持 `device_id`、`device_query` 和正文中已登记设备名。歧义、未知标识和选择冲突保留候选并澄清。
- 范围按显式产品顺序比较，包含两端；规则缺失、跨产品或版本无法解释返回 `UNKNOWN`。固件、驱动、硬件修订独立校验，任一已知不符优先判为 `MISMATCH`。仅匹配资料进入模型和引用。
- 每条消息固定完整设备快照，切换设备和并发提问不串用版本。保存答案时原子核对快照，生成期间更新设备会返回缺口；旧回答保留原快照和原始引用。
- 文件存储兼容 QA-01 状态格式；设备、版本规则和回答重启后仍可读取。PostgreSQL 增加 `002_devices.sql` 及相应适配和可选验收，但真实数据库未联调。


## 外部验收与范围

`done` 表示 QA-02 实现和本地确定性验收完成。尚未取得真实设备清单、正式产品版本顺序规则或内网模型，真实 PostgreSQL、资产系统、模型效果和真实手册匹配均未联调验收。合成资料、外部 HTTP 模型桩和 REPLAY 摘录只证明流程行为。

当前设备解析仅限已登记 ID、名称、别名；不推断未知厂商版本，不复用上一条消息的设备，不实现多轮指代（QA-05）、混合召回与纠偏（QA-03）或实时监控（QA-04）。启动、字段约束和演示方式见 [README](../../../README.md)。
